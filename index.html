SEO Audit

Run a comprehensive, multi-phase SEO audit for any B2B SaaS website. Pulls live data from GSC, DataForSEO, Firecrawl, and InfraNodus. Covers performance teardown, technical infrastructure, content quality, link profile, brand trust, entity architecture, and SERP/AI visibility. Outputs a structured Notion page with prioritized findings and a severity-scored action plan.

SEO Audit

Run a structured, data-backed SEO audit across seven phases. Each phase maps to specific tools and produces discrete findings. The synthesis phase consolidates everything into a prioritized action plan.

This is not a surface-level checklist. Every finding must cite specific data. "Needs better internal linking" is not a finding. "The /solutions/ hub has zero internal links to /product/asset-tracking despite 340 monthly impressions for that query" is.

Phase 1 Fallback (No GSC Access)

If GSC is not connected, use DataForSEO:

dataforseo:dataforseo_labs_google_ranked_keywords(target: "[domain]", limit: 100)
dataforseo:dataforseo_labs_google_domain_rank_overview(target: "[domain]")

Note in the audit that GSC data was unavailable. Findings are estimated from third-party data.

Phase 2: Technical Crawl & Infrastructure

Step 2a: URL Discovery

firecrawl_map(url: "https://[domain]", limit: 500, ignoreQueryParameters: true)

Establish total page count, depth distribution, and path structure.

Step 2b: Crawl Key Pages

Scrape the top 10 to 20 pages by GSC click volume:

firecrawl_scrape(url: "[page_url]", formats: ["markdown", "html", "links"])

For each page, extract: HTTP status, canonical tags, internal link count, word count, heading hierarchy, schema/structured data, meta title/description, robots directives.

Step 2c: Index Performance

For the top 10 pages, run gsc:inspect_url(url: "[full_url]"). Classify each URL:

StatusDefinition
HealthyIndexed, canonical matches, no issues
WeakIndexed but low impressions, possible quality signal
DeadNot indexed, no impressions, candidate for removal or redirect
BlockedBlocked by robots, noindex, or canonical pointing elsewhere

Step 2d: Structured Data Validation

From Step 2b scrapes, extract all JSON-LD/Microdata/RDFa. Validate:

  • Schema types present vs expected for page type
  • Required properties populated
  • Entity consistency (Organization name, logo, sameAs matching)
  • FAQ, HowTo, Article, SoftwareApplication schema where applicable

Step 2e: Performance Analysis (standard+ tier)

Run Lighthouse on 3 to 5 key pages via dataforseo:on_page_lighthouse. Capture Core Web Vitals: LCP, CLS, INP, FCP, TTFB.

Step 2f: Technical Checks

CheckWhat to evaluate
Canonical consistencySelf-ref canonicals, canonical chains, parameter URL handling
Robots accessibilityrobots.txt blocking valuable paths, meta robots conflicts
Internal link consistencyHTTP 200 links vs internal redirects, orphan pages
Paginationrel=prev/next or load-more handling, blog taxonomy pages

HTTPSMixed content, redirect chains

Phase 3: Content Audit

Step 3a: Topical Coverage

infranodus:generate_knowledge_graph(
  url: "https://[domain]",
  context: "Analyzing website topical coverage and content architecture for SEO audit",
  modifyAnalyzedText: "extractEntitiesOnly"
)

Identify topical clusters, entity density, content gaps, topical dilution.

Step 3b: Content Quality

For the top 15 to 20 pages by traffic, evaluate:

SignalAssessment method
Topical weightDepth of primary topic coverage. Cross-ref InfraNodus clusters.
E-E-A-TAuthor attribution, credentials, sourcing, experience markers
Evidence densityStatistics, citations, named sources per 500 words
RecencyLast updated date, freshness of references
Query alignmentDoes content match queries GSC shows it ranking for?
Query dilutionIs the page ranking for too many unrelated queries?
ReadabilitySentence length, vocabulary, scannability
Content-to-code ratioMore template/boilerplate than content?

Step 3c: Cannibalization Deep Dive

Cross-reference Phase 1h data with content analysis. For each pair: determine topical authority winner, recommend consolidate/differentiate/redirect.

Step 3d: Content Gaps

infranodus:search_queries_vs_search_results(
  context: "Finding content gap opportunities between search demand and supply for SEO audit",
  queries: ["[primary_topic_1]", "[primary_topic_2]", "[primary_topic_3]"]
)

Evaluate anchor distribution: branded vs exact match vs generic vs URL. Flag over-optimization or concentration risk (>50% links to one page).

Phase 5: Brand Trust & Entity Architecture

Step 5a: Brand Search

dataforseo:kw_data_google_ads_search_volume(keywords: ["[brand]", "[brand] review", "[brand] alternative"])

Step 5b: Entity Architecture

From Phase 2 crawl data: Organization schema completeness, Person schema, entity consistency across pages, Wikidata/Knowledge Graph presence, sameAs array coverage.

Step 5c: Trust Signals

Check via web search: review presence (G2, Capterra, Trustpilot), privacy/terms pages, company details consistency, about page credibility.

Phase 6: SERP Impact & AI Visibility

Step 6a: AI Overview Impact

For top 10 queries by impression volume:

dataforseo:serp_organic_live_advanced(keyword: "[query]", location_name: "United States")

Check AI Overview presence. Note whether target site is cited.

Step 6b: Query Count Analysis

From Phase 1 data: query diversity trend, zero-click queries (SERP feature displacement), click gap analysis.

Step 6c: AI Platform Visibility (deep tier only)

Test brand presence across AI platforms. Report separately for Google AI Mode, ChatGPT, and Perplexity. Each has distinct retrieval layers.

Phase 7: Synthesis & Action Plan

Severity Scoring

Score every finding: Impact (1 to 5) / Effort (1 to 5). Priority = Impact / Effort.

Action Plan Categories

CategoryTimeframe
Quick wins1 week. Title/meta rewrites, canonical fixes, redirect cleanup.
Short-term2 to 4 weeks. Content consolidation, schema deployment, internal linking.
Medium-term1 to 3 months. Content creation, link building, architecture changes.
Strategic3 to 6 months. Entity buildout, topical authority, AI visibility programs.

Framework Mapping

Map findings to Exalt Growth frameworks where they genuinely fit. Do not force it.

  • PoI signals: Which of the 7 signals are weak?
  • Entity-First pillars: Gaps in Foundation, Structure, Signals, or Measurement?
  • EGOS modules: Which module addresses the fix?

Output to Notion

Read references/notion-template.md before writing the page.

Publish as a Notion subpage under the provided parent page ID:

Notion:notion-create-pages(
  parent: { page_id: "[parent_page_id]" },
  pages: [{ properties: { title: "SEO Audit: [Domain] - [Tier] - YYYY-MM-DD" }, content: "[rendered template]" }]
)

Health score: weighted composite (20% performance trend, 15% index health, 15% technical hygiene, 20% content quality, 15% link health, 15% entity architecture). Score conservatively. Most SaaS sites land between 40 and 65.

Return the Notion URL at the end.

Voice Rules

  • No em dashes. No exceptions.
  • No filler phrases.
  • Sentences under 17 words.
  • Atomic facts: each finding stands alone.
  • Front-load the sharpest diagnostic.
  • Tables for comparisons and metrics. Prose only when diagnosing.

Sound like a senior SEO strategist delivering a diagnostic, not a tool regurgitating data.

Failure Modes to Avoid

  • Listing technical issues without prioritization. Action plan must be severity-ranked.
  • Generic recommendations ("improve site speed"). Tie to specific URLs and metrics.
  • Treating all findings as equal weight. High impact/low effort comes first.
  • Reporting raw tool output without interpretation. Every data point needs a "so what."
  • Skipping the segment breakdown. Aggregate metrics hide the story.
  • Conflating brand and non-brand performance.
  • Over-indexing on technical issues when content or links are the real bottleneck.
  • Ignoring entity architecture. For AI visibility, entity completeness is foundational.
  • Treating AI search as monolithic. Each platform has distinct retrieval layers.
